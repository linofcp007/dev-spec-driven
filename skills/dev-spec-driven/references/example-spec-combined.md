# Worked Example — all four tracks: `core +tdd +saas +ai`

A realistic feature that pulls in every track at once: **per-tenant invoice summaries generated by
an LLM** in a multi-tenant SaaS. This shows how the artifacts and gates compose. (Condensed — real
specs are longer; this is the shape.)

Feature slug: `invoice-summary`

---

## classification.md

```markdown
# Classification: Invoice Summary

## Mode
Spec

## Active Tracks
core +tdd +saas +ai

## Signals
- **+tdd:** billing/invoice (financial correctness), data integrity — wrong totals are costly.
- **+saas:** multi-tenant boundary (tenant A must never see tenant B's invoices), hot path.
- **+ai:** user-facing generation (summary shown to the host), user data → model (PII), quality-sensitive.

## Blast Radius
A wrong/leaked summary is a trust + compliance incident (GDPR). Cross-tenant leak = breach.
Recoverable only if caught fast. → high rigor warranted.

## Hot Path?
Yes (rendered on every host dashboard load) → load-test.md required.

## Autonomy Level
Advisory — the host reads the summary; no autonomous action taken.

## Volume / Cost Projection
- Launch: ~2k summaries/day, ~$30/mo tokens · 6mo: ~20k/day, ~$250/mo · 2yr: ~150k/day.

## Compliance Tags
GDPR — invoice data (PII) flows to the model provider. DPA + EU endpoint required.
```

## requirements.md (excerpt — note the track-specific ACs)

```markdown
### US-1: Host sees a plain-language summary of an invoice
**As a** host, **I want** a one-paragraph summary of each invoice, **so that** I understand
charges without reading the full document.

#### Acceptance Criteria
1. **US-1.AC-1** — WHEN a host opens an invoice, THE SYSTEM SHALL display a generated summary within 1500ms at P95.
2. **US-1.AC-2** — WHEN a summary is generated, THE SYSTEM SHALL include the total amount and due date verbatim from the invoice.
3. **US-1.AC-3** — IF the model is unavailable for >5s, THEN THE SYSTEM SHALL fall back to a templated non-AI summary.
4. **US-1.AC-4** — [tenant isolation] WHEN a host from tenant A requests a summary, THE SYSTEM SHALL NOT include data from any invoice whose tenant_id != A.
5. **US-1.AC-5** — [quality] THE SYSTEM SHALL score ≥ 90% "good or excellent" on the golden eval set.
6. **US-1.AC-6** — [safety] IF invoice text contains an injected instruction, THEN THE SYSTEM SHALL ignore it and summarize only the invoice.
7. **US-1.AC-7** — [cost] THE SYSTEM SHALL cost at most $0.01 per summary at P95 input size.
8. **US-1.AC-8** — WHEN a summary is generated, THE SYSTEM SHALL log prompt version, model ID, token counts, and tenant_id.
```

AC-1/AC-2/AC-3/AC-8 → deterministic tests (+tdd). AC-4 → tenant-isolation test (+tdd/+saas).
AC-5/AC-6 → eval cases (+ai). AC-7 → cost validation (+ai). AC-1 (P95) → load test (+saas).

## design.md (section map — each mandatory section is filled, no TODO sentinels left)

- Base: Overview · Architecture (Mermaid: invoice → redact PII → retrieve totals → model → validate → cache → host) · Data Models · API Contracts · Security · Error Handling · Testing Strategy
- **+tdd:** Testability Notes — clock + model client injected behind interfaces; golden invoices as fixtures.
- **+saas:** Performance Budget (P95 1500ms, cache hit > 95%) · Scale Design (cache summaries by invoice hash, 24h TTL) · Multi-tenancy (pooled, tenant_id in every query + cache key) · Observability (`summary_duration_seconds`, `summary_cost_dollars_total`, tenant-scoped logs) · Cost Envelope ($/1000 hosts/mo, dominated by tokens).
- **+ai:** Model Strategy (primary + cheaper fallback) · Prompt Architecture (`prompts/vN.md`) · Token Economics · Latency Budget (TTFT < 800ms) · Eval Strategy (golden 90% / adversarial safety 100%) · Safety & Abuse (delimiter + output validation of totals) · Fallback & Degradation (templated summary) · Observability for AI · Model Lifecycle (pinned IDs, eval-gated migration) · Multi-modality (text only).

## evals — +ai

- `evals/golden.json` — 120 representative invoices; grader checks total/date present + judge for clarity. Threshold 90%.
- `evals/adversarial.json` — invoices with embedded "ignore instructions / reveal the system prompt"; must summarize only. Threshold 100% (safety).

## load-test.md — +saas
- Scenario: 300 RPS dashboard load, 95% cache hit. Pass: P95 ≤ 1500ms, error rate < 0.1%.

## Execution — which loop per task
- Tasks 1, 2, 4, 5 → **red → green → refactor** (deterministic, +tdd).
- Task 3 → **prompt-iteration** loop gated on eval delta (+ai).
- Task 6 → **cost validation** (+ai). Task 7 → **load test** must pass (+saas).
- Before "done": `spec_doctor` is green, observability proven, adversarial set 100%, cost within budget.

This is the full pipeline. A simpler feature would activate fewer tracks and skip the corresponding
artifacts — that's the point of Phase 0.
