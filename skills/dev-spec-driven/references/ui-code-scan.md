# The UI code scan — what `spec_scan {designSystem}` reads, judges and reports

`spec_scan {designSystem: true}` / `dev-spec design-system` (the project) and `spec_scan {designSystem: true, name}` /
`dev-spec design-system <feature>` (a feature) compare the code with the registry
([ui-design-patterns.md](ui-design-patterns.md) → The registry). This file says what that scan reads in the project's
files and what it doesn't, what a raw value is against the project's own scale, the units table, and the UI checks it
runs on a feature's view and style files and on the project's — and how a team switches one off.

---

**What the code scan reads — and what it doesn't.**

| | Read | Not read |
|---|---|---|

a story's or a test's call is no sign), gives it to `useContext` / `use` or provides it (`<X.Provider>` — a part of the component named `Provider` is that part), or reads a part as an object (`Button.Sizes.Large`). **what a file exports that is no component by its declaration** — a type, a context (`createContext(…)`), an object, a schema, `cva(…)`, any other call, a hook, a re-export of another file of the project under its own name (`export { X } from "./x"`, `export *`) — a PascalCase function that shows it is none — it takes a component (`function WithTheme(Component)`) or three parameters, or the file calls it as a function (`FormatPrice(value)`) and it renders nothing itself —, a call given an object, a list or an element first, whatever JSX it holds (a table's columns, a router's routes, `renderToString(<p />)`), a call given no function and no component's name or string first — its JSX is an element handed over: `mount(root, <App />)`, `createRoot(el).render(<App />)` —, an element in parentheses (`const Logo = (` then `<svg />`), a function called at once, the lines of a template literal (a code sample) — unless the project renders it, above; a literal (a string, an object, a number) never; and a component the reader cannot tell: one of those NO file of the project renders where the reader sees it (a kit whose apps live in another repository; a name rendered only past a bound, or by a default import under another local name in a file that writes none of the names asked; through an alias only a config's `references`, a package's config, `package.json`'s `imports` or a bundler's alias writes; through a re-export by CommonJS, or under another name by a file that is neither a component file nor a component folder's barrel when only files that write no asked name render it; by a markup file with no import — Nuxt's auto-imports, MDX's `mdx-components.tsx` —, a one-word Vue tag, a Pug template, a dynamic component; by a factory not imported from its library — `const e = React.createElement`, a global `wp.element.createElement` —, a factory's argument written with a cast (`X as Y`) or in parentheses, or only in a `.ts` file when no weak name is asked; through a workspace package's root entry other than its `src/index` / `index`), one in a lower-case `.js` file or in a `.ts` file other than a component folder's barrel — add its row by hand, or cite it as `Card (CardHeader)`. (The other way, taken for a component: a PascalCase helper, a part on an imported name that is none (`Button.Sizes = Sizes`), a call whose function renders (`memoize((n) => <Icon />)`) — each while the project never calls it nor reads it as an object —; a top-level alias of an imported name that is none; a call given a string or a capitalised name first whose JSX is an element handed over (`t("hint", { link: <a /> })`, `cloneElement(Base, { icon: <Icon /> })`), one given a method beside an element, given an object with a `render` method, curried around an import (`configureStore(options)(Reducers)`); a class with a `render` that returns JSX the project never constructs. A stray backtick — in an element's text — hides what stands up to the next one, and a template inside another's `${ … }` over lines is read as code; since 1.35.3 a regular expression's backtick is the regex's and a string right after `return` / `case` is a string) |
| Libraries | the UI libraries among the `dependencies`, `devDependencies` and `peerDependencies` of the project's `package.json` files — the root's and its workspace packages': the folders it declares in `workspaces` (package.json), in `packages` of `pnpm-workspace.yaml` / `lerna.json` (Lerna's default `packages/*` only when nothing declares a workspace) or in `projects` of `rush.json` (each `projectFolder`), and the ones a workspace package declares for its own folder (its `workspaces`, two levels deep, as many as can be asked) — a name, a `*` within one, `**` two levels deep, never inside a folder that is a package itself, a brace list expanded (`{apps,libs}/*`, 20 patterns a list), a `!negation` taking out the folders the patterns before it give in `package.json` (npm's order) and wherever it stands in `pnpm-workspace.yaml` (pnpm's; a name, `*`, `**`, a brace list; a workspace package's own for its folder; 200 alternatives, past them said) — or, when it declares none and its root is no app of its own (its `dependencies`), the folders one level down (`frontend/`, `client/`) and, when that level holds no package and the root does not look like a library (not `private`, with a `name`, `peerDependencies`, `main`, `module` or `exports`), the next (`apps/web/`); a bound of that guess is never said — and a workspace file that names nothing it can read is looked through one level. The first 100 workspace manifests, 50 patterns that hold a `*` and 1,000 folders named in full (200 characters and 12 segments each), 200 folders listed, 2,000 asked: past a bound — or for what is declared and not followed (a brace list of one, a `rush.json` that is no JSON, a third level of nesting) — the report says `workspace-manifests` | a manifest three levels below a root that declares no workspace (two, when the first level holds a package), a folder beside the declared ones, a sub-folder of a root that is an app itself (its `docs/`), two levels below one that looks like a library (its `examples/`); a link, a dot folder, `node_modules` |
| Tokens | CSS custom properties, Sass variables and Less variables of `tokens.css`, `_variables.scss`, `variables.less`, `theme.css`…; the leaves of `design-tokens.json` / `*.tokens.json` anywhere, of `theme.json` anywhere but under a folder — at any depth — that holds something else by that name (`store/`, `models/`, `server/`, `types/`, `hooks/`, `scripts/`…), and of a plain `tokens.json` at the project's root or in a `styles/` `theme/` `design/` `tokens/` `ui/` folder (`packages/ui/src/tokens.json` counts: `src/` is looked through); a global stylesheet, wherever it lies (`app/globals.css`, `src/index.css`, a Django `static/` folder, a WordPress theme's `style.css`), with five or more custom properties: every one of a sheet named `globals` / `global`; in a sheet named `index`, `main`, `app`, `styles` / `style`, `base`, `root`, `site`, `application`, `tailwind`, `custom` or `input` (`.css` / `.scss`) those declared FOR THE WHOLE PAGE — on `:root`, `html`, `body` (alone, qualified or in a list, under `@layer` / `@media` too), in Tailwind's `@theme` or a theme plugin's `@plugin`, in a block at least half of which overrides them (`.dark`) or a mixin `:root` includes. A Sass partial of one of those names counts (`_base.scss`). **Only a design value is read out of a file** — a colour, a number with or without a unit, a keyword, a `{reference}`, a function whose arguments are design values themselves (`rgb()` `var()` `calc()` `map-get()`), Sass arithmetic and `#{…}`, alone or as a list. A declaration with no `;` is read when its block or its file ends there, and line by line in an indented `.sass` file | values kept in a JS / TS / YAML file (`tailwind.config.ts` anywhere, `theme.ts`, a `tokens.ts` in those places): the file is listed as a source, its values are not. A plain `tokens.*` anywhere else (`src/tokens.json`, `src/auth/tokens.ts`) and the singular `token.json` are no token files. A stylesheet under any other name (`brand.css`, `card.component.scss`: name a global one in `_Token sources:_`); one that declares its custom properties on a selector of its own (a component's `.card { --card-bg: … }`, in any folder), on `:host`, on a descendant (`body .card`) or — unless it is named `globals` — on a class or an attribute alone with no `:root` block beside it; a CSS module; a sheet with fewer than five such properties; a component rule that re-points one page-wide token beside its own variables — a block is a theme when at least half of what it declares overrides page-wide tokens, and the threshold has two edges: a theme that adds more names of its own than it overrides is not read either (add those rows by hand), a rule of two variables that re-points one is; a twin that brings no name of its own (`main.min.css`, a second app's identical `globals.css` — no further source, still a token file; of identical sheets the source is the likeliest name, then the root-most, then the first by path, which may be a built copy — `public/css/app.css` beside `resources/css/app.css`: `_Token sources:_` is in sync when it names that one). Past 100 candidate files the search ends, the likeliest names (`globals.css`, then `main.css` / `styles.css`…, then `index.css`) and the root-most first. A parameter or a map's key inside parentheses (`@mixin x($border: …)`) is no token. **Any value that is no design value** — a font stack, any `url(…)`, a quoted string, free text, a function holding any of them, and so any credential a file named for tokens may hold: never printed or written (a stylesheet's token, a `$value` or a `value` beside a token `type` is listed by its name alone — so is a composite token, a shadow or a typography, and a declaration that goes on below its line —, any other JSON leaf not at all). **A JSON file that does not show it is a design file** — no design-tokens format (`$value`, with a `$type` of one word when it has one; `value` beside a token `type` that is no word any data holds, such as `time`) and no 3 / 6 / 8-digit hex, functional colour, length or `{reference.path}` in it: a map of numbers (its key names would be printed), a plain `{"spacing": {"sm": 4}}` — is not read: add its rows by hand. **A JSON key that is not words** — a key is printed too: letters, digits, or the two with at most two switches between them (`gray900`, `2xl`, `a11y`; a colour's own 6-digit hex counts), no word of 40 characters —, so a key shaped like a GUID, an API key, a hash or a JWT is left out with everything under it, and so is a token keyed `w1280h720`: add that row by hand. A second layer, not a guarantee — some keys shaped like an API key still pass, the shorter the more often: keep credentials out of files named for tokens. (A stylesheet's own identifiers are listed as written.) Beneath a credential key (`…token`, `…secret`, `…password`, `api_key`…, and `pin` / `otp` / `passcode`) nothing but a literal that says design or a `{reference.path}` is listed, and a free string right under one (those last three aside) makes the file no token file. What stays printed: an identifier the author chose — a function's, a variable's or a reference's NAME — with the value it is part of. Past a bound that cut something — 20 token files, 100 files named like one, a token file longer than 256K characters, 1,000 tokens — the report names it and never says the two are in sync |
| Registry paths (a stale row) | a path cell naming a code file of the project — with a blank, behind a markdown link, beside a note, with a `:12` anchor: gone when no file it names is there | a package (`next/link`), an alias (`~/components/…`), prose or `n/a`, a glob, a path without a file extension, a root-level file, a path whose first folder no longer exists, a document or an image a note cites; a row that also names a file that is there is not stale |
| Raw values | a hex or functional colour in a string, an attribute or a Tailwind `[#…]`; `margin` / `padding` / `gap` / `font-size` / `border-radius` in px / rem / em in a stylesheet, a `<style>` block (a `.vue` / `.svelte` / `.astro` / `.html` file's, styled-jsx's in a `.jsx` / `.tsx`) or a CSS-in-JS declaration line; a Tailwind arbitrary size | a size in a JSX `style={{…}}` object; a token file — a source or its twin —, whole (a rule with a raw value written in the sheet that holds the tokens is not reported); the further lines of a value written over several (`box-shadow: …,` is read by its first line); an anchor or a selector target (`href="#abcdef"`, `data-bs-target="#add"`, `querySelector("#add")`, a 3 / 4-digit `gsap.to("#face")`), a comment, a selector, `rgb(var(--x))`, a 1px hairline, a value built from a variable or `calc()` |

### UI checks — defects whatever the taste

The feature report also reads its view and style files for defects no taste excuses (`uiChecks`). For a +ui feature, a
warning of `spec_finish` too, never a blocker: `zoom-disabled` (zoom blocked — WCAG 1.4.4), `img-no-alt` (an `<img>`
with no alt — 1.1.1), `outline-removed` (`outline: none` on an element, `*` or `:focus` with no focus style in the
feature's files or the project's first 48 stylesheets — past them, named unjudged — 2.4.7), `click-no-keyboard` (a click
handler on an element the keyboard cannot reach: no `tabindex` — a role or a key handler alone is not enough — 2.1.1),
`paste-blocked` (an inline paste handler that cancels — 3.3.8 at a sign-in or code step, a usability defect elsewhere),
`font-size-viewport` (text sized in viewport units alone — `font-size: 5vw`, `text-[5vw]` — which
zooming does not enlarge: WCAG 1.4.4, failure F94; a size with a rem / em term zooms: `clamp(1rem, 0.5rem + 2vw, 2.5rem)`).
F94's note — a size media queries adjust may not fail — keeps it to what is certain: a stylesheet's (a `<style>` block's)
size only when that file declares no font size inside `@media`, `@container`, `@supports` or a Sass `@include` (nested
too); an element's own `style` attribute, never a component's prop or a CSS-in-JS object (`sx`, `css()`, `style()`);
a bare `text-[…vw]` only when its file holds no size under a variant (`md:text-6xl`; not a colour, nor a key of your own:
`md:text-hero`). Neither the stylesheet's
nor the bare one is judged in a file read in part (past 256K, a line past 2,000 characters). An override in another file
is not seen: silence that one. An Astro `<style define:vars>` block's first at-rule reads as a selector: silence what it
gives.
In the report alone: `transition-all` (kits ship it), what a bound cut. Silence one with a comment
`ui-check-off: <rule-id> <why>` on its line (a declaration's, a class's) or the line above — `//`, `/* */`, `<!-- -->`,
not Blade's or Twig's: counted, never listed; only this comment silences (a linter's is not read) — an `<a>` a parent gives its
href (Next's `legacyBehavior`) is one to silence. A doubt is never judged: a named paste handler, a click whose content
holds a control, a component (an icon or a text component too; a bound Vue `<component :is>` in it is none) or a slot, or no text (an icon or an image alone), a
spread (`{...props}`), a tag in an attribute or a one-line template literal, Pug, a tag past 100 attributes or 30 lines.

### The project's UI checks

`spec_scan {designSystem: true}` / `dev-spec design-system` (no feature) also run the UI checks over the project's view and
style files — an inventory, `uiChecks`: `read`, `total`, `silenced`, `byRule` and `rules` (per rule its level, the files
holding one, the first place), `facts`, `limits`. Counts, never a list, never a finish warning: each feature's report lists
its own. The tool and the CLI ask for it; the engine's own default runs none. Stylesheets are read first, then the shorter
path — at most 5,000 files and 32 MB (`ui-files`, naming the outline removals it left unjudged), each file's first 256K and
a line's first 2,000 characters (`view-size`, `line-length`; a tag past 30 lines, `tag-length` — each with a count and the
first file): its own limits, never the report's `limits` or `truncated`. A stylesheet past 256K (a compiled bundle) is
counted in `view-size`, never checked: its focus styles excuse nothing, so the inventory may warn of a removal a feature
report excuses by them. A test, a story, a mock or a fixture is no view file. `outline-removed` keeps its rule — any focus style in any file read excuses every removal —, so the removals a feature
report leaves unjudged past the project's first 48 stylesheets are judged here; a cut pass that read no focus style judges
none. A feature report looks for a focus style in its own files and the project's stylesheets alone, so it may warn of a
removal the inventory excuses by one in another view file: check that the removal's elements
get it, or silence it.

The fact `no-reduced-motion` (WCAG 2.3.3, AAA): the view files declare motion — an animation, a transform's transition,
smooth scrolling — and none of the files read mentions reduced motion (`prefers-reduced-motion`, `motion-safe:` /
`motion-reduce:`, `useReducedMotion`). Said only when no view read was cut (the walk, `ui-files`, a file's 256K); a
script's mention counts too — a test setup's outside a test folder included (2,000 by shorter path, 8 MB: `motion-scripts`).

**Off for the project.** `_UI checks off: <rule-id> (reason)_` — a line of its own in design-system.md (never a list item
or bold), the marker in English, ids bare or in a code span, entries separated by commas
(`_UI checks off: transition-all (kit code)_`) — switches a UI check or a project fact off everywhere: the inventory, every
feature report (`off`: the rule, its reason, the findings it hid) and so finish — counted, never listed (an inline-silenced
finding stays `silenced`). An entry with no reason in parentheses, an id that is no check or fact, another shape or one
past the first 50 entries is not applied, and the report says why (`offIgnored`, `why`: `no-reason`, `unknown-rule`,
`unreadable`, `past-bound`). Creating design-system.md for the marker alone enrols the project in the registry: a written
finish adds the feature's New components to it, and from its first component doctor's `ui-design-system` checks every
design's rows against it (a refusal at size m / l) — without a registry, use the inline comment. A what-input modality
rule (`[data-whatintent='mouse'] *:focus { outline: none }`) is judged as written: silence it with an inline
`ui-check-off: outline-removed` on that rule — the marker would switch off every removal of the project.

### Raw values against the project's scale

A feature report judges each raw value against the project's own scale — the registry's token rows with their values, then
the code's tokens the registry does not list:
- **Colours** — hex, `rgb()`, `hsl()`, `oklab()`, `oklch()` (`none` reads as 0): `token` names the token the value IS (the
  nearest of several), in any notation — exact within one notation, across two within the rounding of the pair as written
  (0.011 ΔEOK with an HSL side, 0.001 otherwise; an HSL side against a hex or `rgb()` also both ways: the other in HSL
  rounds to its numbers or the HSL paints it, 8 bits a channel — `#05787d` is `hsl(183 92% 25%)`, `#eeeff2`
  `hsl(220 14% 94%)`, `#18181b` is not `hsl(0 0% 9%)`), alphas within 0.01; `near` {`token`, `delta`} the nearest within
  0.02 ΔEOK — a hint, never the token's colour (Tailwind's zinc hexes are not shadcn's neutral; its `oklch()` zinc is the
  `hsl()` one, within 0.011). `hwb()`, `lab()`, `lch()`, `color()` and a named colour match by text alone.
- **Fonts** — a `font-family` stack ending in a generic family, by its first family, against the registry rows' font tokens
  only (a code token's stack is never read; one ending in a named emoji font is no stack). Read when the registry holds one.
- **Motion** — a `transition` / `animation` declaration's literal times above 1 ms and easing functions (`cubic-bezier()`,
  `steps()`, `linear()`; never a keyword), Tailwind's `duration-[…]` / `delay-[…]` / `ease-[…]`: `token` when each literal is
  a duration or easing token's, never a nearest. Read when the scale holds such a token.
- **Sizes** stay raw: no size scale is guessed.

`counts` gains `font` / `motion` only when read; each has its own bound, a file's first 200 (`font-values` /
`motion-values`, with the first file). `groups`: the values read twice or more, by what each is (`#1E40AF`, `rgb(30 64 175)`
and `text-[#1e40af]` are one; a utility without its variants), the most frequent first — the first 50, `groupsTotal`. Finish
still counts colours and sizes alone.

**Token values.** The project report's `drift` (the first 50, `driftTotal`) lists a registry token the code declares with
another value IN THE SAME NOTATION — one colour each, or one number each with one unit (`s` read as `ms`): `#3b82f6` against
`hsl(217 91% 60%)`, `16px` against `1rem` are not compared, nor a name the code declares with two values or more (a theme,
a twin sheet). `gone` lists the `_Token sources:_` files that no longer exist. Neither changes `inSync`: it compares names.

**The units table** — the team's convention of which units each property takes, in design-system.md (its shape and an
example: [steering-templates.md](steering-templates.md) → design-system.md). A feature report's `units` lists each
declaration whose value takes, outside parentheses, a unit its row does not give (never `0` or a unitless number; a negative
length counts: `-8px`), and a Tailwind arbitrary size in any unit (`p-[10px]`, `-mt-[12px]`, `text-[2vw]`) by the property it
sets: {`findings` — the first 50: `file`, `line`, `property`, `value`, `unit`, `allowed` —, `total`, `byProperty`}. The
project report's `unitsTable` {`rows`, `unread`, `past` — rows past the first 50}. A report — never finish or doctor; a UI
task's brief quotes its rows (their first 400 characters) — and no default: without the table both are null.

**DESIGN.md** is not read; its own CLI writes a file that is:
`npx @google/design.md export --format css-tailwind DESIGN.md > theme.css` (a token file by its name). **Breakpoints:** both
reports end in `breakpoints`, the widths the visual review captures ([ui-responsive.md](ui-responsive.md) → The project's
breakpoints) — its own limits (`breakpoint-widths`, `breakpoint-line`) never make a report truncated. **Doctor's
`ui-states`** reads the design's state matrix, not the code ([ui-design-patterns.md](ui-design-patterns.md) → The states
every view needs).

### Deprecated components the code still imports

While the registry marks a row `_Deprecated:_`, the project report adds `deprecatedUses`: for each such row the code holds a
component file for — the rows still imported first —, the files that still import it (`files`, the first 3 by path;
`filesTotal`), its replacement as doctor names it (`use`) and its component files (`paths` — a namesake's importers count
too); `unlocated`: rows whose name no component file the scan reads gives — a .tsx / .jsx / .js / .vue / .svelte / .astro
file or a component folder's index (a library's, an Angular or a Blade one). A row named by its file is its **module** — any
import of it counts (renamed, default, type-only, `require`, a non-component export, a namespace's member, an SFC with or
without its extension) — and its components, followed through `export *` and a component folder's barrel; a component a file
exports beside its own counts by its **name** (a default import too, when it is the file's default). An .mdx / .vue tag no
import binds is counted apart (`unbound`). Not seen (its `note`): a `.ts` file, a dynamic `import()`, a module only a
bundler's alias or a virtual module names, a re-export under another name outside a component folder's index, a tag an
auto-import names by its folder, a non-component export or a type through a barrel. Nuxt's `<BaseCard>` is such a tag
(`components/base/Card.vue`), `import type { X }` from a component folder such a type. **No import found is not unused.**
Its `limits` (`usage-files`, `deprecated-follow`) never touch the report's `limits` or `inSync`.
